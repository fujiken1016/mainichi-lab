Qiita記事を19本書いて分かった、「伸びる型」が自分には効かなかった話

2026年10月21日 ／ フジケン

この数週間でQiitaに記事を19本書きました。書く前に、Qiitaの記事を何万件も集めて「どんな記事が伸びるか」を調べた分析を読み、そこに出ていた特徴（画像が多い、見出しが多い、リンクが多い、長い）に合わせて書いています。この記事は、その結果を自分の数字で確かめた記録です。

先に結論を書くと、PV（読まれた数）は出ました。一方、LGTM（いいね）とストック（保存）はほとんど付いていません。他の人の分析が間違っているのではなく、「誰が書いたか」を動かせない状態では型の効き目が見えない、というのが今のところの読みです。

1. 大規模分析が言っていたこと

書く前に、Qiita（一部はZennも）の記事を集めて分析した3本を読みました。母数も指標もそれぞれ違うので、並べて整理します。

表1：3つの大規模分析が見ていたこと（2026年10月20日に各記事を開いて確認）
記事母数と指標言っていたこと
Qiita 45,415記事の分析45,415件（主分析は投稿72時間以上の44,334件）。指標は10いいね以上になる確率（出典：同記事、2026年10月20日確認）同記事（2026年10月20日確認）によると、タグ5個・本文5,000字以上・見出し3個以上・リンク3個以上が伸びやすい。タイトルのコロンは取りこぼしやすい。著者自身が「相関であって因果ではない」と明記
Qiita 7.7万件の分析約7.7万件のうち成熟した39,222件。指標は10いいね以上の割合（全体8.2%）（出典：同記事、2026年10月20日確認）同記事（2026年10月20日確認）では、1,000字未満は1.6%、見出し5個以上とタグ5個で上がる。更新やコメントは「伸びた結果」の可能性が高いと書いている
QiitaとZenn 約5,500本の分解Qiita API v2とZenn APIから収集。調査期間はQiita1週間・Zenn10日いいね数の説明力の大半は「誰が書いたか」と外部での拡散。記事の中身の分はQiitaで約1割

3本に共通していたのは、見出し・タグ・文字数・リンクといった「書き手が自分で決められる要素」で上がり下がりが見える、という点です。一方で3本目は、いいね数の説明力の大半は著者と外部での拡散にあるとも書いていました。この2つは矛盾しているようで、矛盾していません。同じフォロワー数の人だけを比べれば型の差が見え、全体を比べればフォロワー数の差が見える、ということだと理解しました。

2. 自分で取ったデータ

他の人の分析をそのまま信じる前に、自分でも同じことをやってみました。2026年9月3日に、Qiita APIで4つのタグ（ClaudeCode、Claude、AIエージェント、生成AI）の記事を取得し、重複を除いて1,466本を集めています。全体ではLGTMの中央値が0、LGTM 0の記事が66.3%でした（同日の取得時点）。

ここからフォロワー20人以下の著者だけに絞った1,067本で、LGTM 3以上を「当たり」と数えました。基準のhit率は6.7%です（2026年9月3日取得分）。

表2：フォロワー20人以下の著者 1,067本での「当たり」（LGTM3以上）の出やすさ（2026年9月3日取得・基準のhit率6.7%）
要素本数hit率基準との比
画像6枚以上7417.6%2.63倍
外部リンク8本以上26713.1%1.96倍
h3見出し10個以上15514.2%2.12倍
本文6,000字以上43810.0%1.49倍

本文2,000字未満1130.9%0.13倍

文字数は「長いほどよい」ではなく、6,000字あたりに境目がありました。2,000字未満はほぼ当たらず、6,000字を超えるとhit率は10%前後で横ばいです。画像の枚数は、mermaid図で代用しても効果が見えず（8.6%）、画像として貼った記事のほうが高くなりました。

ただし、これは相関です。図を6枚入れる人は、ほかの部分も丁寧に書いている可能性があります。「図を足せば当たる」とは読めません。

3. 19本書いた結果

表2の型に合わせて、図7枚、外部リンク14〜29本、h3見出し14〜38個、本文は約1.2万〜2.9万字の記事を書きました。台帳に残っている最初の9本の数字は次のとおりです。

PVは1本目から日に100〜170ほど付きました。ところがLGTMが付いたのは、20,489字・h3見出し38個の1本だけです。それ以外の記事は、図を7枚入れても、リンクを20本以上貼っても、LGTMとストックは0のままでした。

自社サイトへの送客も出ていません。2026年10月2日の確認では、記事に置いた受注窓口へのリンクに対応するキャンペーン名が、GA4（9月21日〜10月2日）に1件も記録されていませんでした。読まれてはいるのに、クリックされていないということです。

4. 食い違いをどう読むか

表2では型に合う記事のhit率が上がり、自分の19本ではほとんど当たりませんでした。この差について、分かっていることと分かっていないことを分けて書きます。

  • 分かっていること：フォロワー0の著者はLGTMの基準値が0に近い。2026年9月3日取得分で全体の66.3%がLGTM 0だったので、0は失敗の証拠にならない
  • 分かっていること：PVはタグの大きさ（そのタグをフォローしている人数）と連動して動いた。記事の質より、どこに置いたかの影響が大きく見えた
  • 分かっていないこと：型が効かなかったのか、サンプルが19本（うちLGTMが付いたのは1本）で少なすぎるのか。ここは切り分けられていない
  • 分かっていないこと：読まれたのにストックされないのは、内容が「読み物」で、手元に置く道具になっていないからかもしれない。これは仮説で、まだ検証できていない

3つの分析が書いていたとおり、LGTMの多くは「誰が書いたか」と外への広がりで決まるのかもしれません。そうだとすると、フォロワーが少ないうちは、型を磨くよりも先に別の測り方が必要です。

5. 測り方を変えたこと

LGTMを撤退や継続の判断に使うのをやめました。代わりに、次の3つで見ています。

  1. PV（自分の記事はAPIで取れるが、他人の記事は取れない）
  2. ストック（フォロワー数の影響を受けにくい指標として）
  3. 記事から自社サイトへ実際に来た人数（GA4のキャンペーン名で数える）

観測した数字には日付をつけて残し、次に測る日も決めておきます。「たぶん伸びる」で書くのをやめ、「何を測れば伸びたと言えるか」を書く前に決める、という順番に変えました。

まとめ

  • 大規模分析の型は、同じフォロワー数の人同士を比べるときに見える——フォロワー0でそのまま真似しても、LGTMには出にくい
  • LGTM 0は失敗の証拠ではない——2026年9月3日取得分では全体の66.3%がLGTM 0。判断にはPV・ストック・送客のほうが向いている
  • 数字は観測日つきで残す——この記事の数字は、2026年9月3日・9月14日・10月2日時点のものです

次の1アクションとして、自分の記事のAPI値を、記事ごとに公開日・PV・LGTM・ストックの4列で表にしてみてください。それだけで「何が動いて何が動いていないか」が見えます。
